# Curso 5: Portfólio, Currículo e Processo de Aplicação
### (Fase 5 do plano — Semanas 21-26+)

Essa fase é onde tudo que você construiu vira, de fato, uma vaga. Muita gente boa tecnicamente perde oportunidade por erro de posicionamento — vamos evitar isso.

---

## Módulo 1 — Montando o portfólio final

### Aula 1.1 — Os 3 projetos que você deve ter até aqui
1. **Projeto do Curso 1**: script CLI com TypeScript, mostra fundamentos de lógica
2. **Projeto do Curso 2**: API REST com autenticação e banco de dados relacional
3. **Projeto do Curso 3**: aplicação full-stack completa, no ar, com link público

Se algum estiver fraco, **é melhor melhorar um projeto existente do que criar um quarto pela metade.** Recrutador olha qualidade, não quantidade.

### Aula 1.2 — Projeto "carro-chefe" com tema pessoal
Dado seu background, um projeto ligado ao seu servidor de Tibia tem valor extra: mostra paixão genuína e resolve um problema real que você entende de verdade (não é "mais um todo-list de tutorial").

Ideias:
- Dashboard de estatísticas de guilds/jogadores do seu servidor
- Painel administrativo pra gerenciar itens, quests ou eventos
- API pública que expõe dados do servidor (ranking, highscores) pra outros consumirem

**Isso deve ser o projeto que você abre primeiro numa entrevista.** Ele gera perguntas melhores do que um clone genérico de app de tarefas.

### Aula 1.3 — README de nível profissional
Todo projeto do portfólio precisa ter, em inglês:
```markdown
# Nome do Projeto

Uma frase clara sobre o que o projeto resolve.

## Live Demo
🔗 https://seuprojeto.vercel.app

## Screenshots
[imagem aqui]

## Tech Stack
Node.js · Express · TypeScript · MySQL · Prisma · React

## What I learned
2-3 frases sobre desafios técnicos reais que você resolveu.
```

O campo "What I learned" é subestimado — mostra maturidade e reflexão técnica, algo que recrutador júnior raramente vê.

## Módulo 2 — Currículo

### Aula 2.1 — Formato ATS-friendly
ATS = Applicant Tracking System, o software que filtra currículos antes de um humano ver. Regras:
- Uma página só
- Sem tabelas, colunas complexas ou imagens (ATS não lê direito)
- Fonte simples (Arial, Calibri), sem enfeites
- Formato PDF gerado a partir de texto real, nunca imagem escaneada
- Nome do arquivo: `SeuNome-Dev-CV.pdf`

### Aula 2.2 — Estrutura recomendada
```
[Nome]
[Email] | [LinkedIn] | [GitHub] | [Localização: Brazil (Remote)]

SUMMARY
2-3 linhas: quem você é, sua stack principal, o que busca.

TECHNICAL SKILLS
Languages: JavaScript, TypeScript
Backend: Node.js, Express, Prisma
Frontend: React
Database: MySQL
Tools: Git, Docker (se souber), Postman

PROJECTS
[Nome do projeto] — [link ao vivo] — [repo GitHub]
- O que o projeto faz, em 1 linha
- Stack usada e 1 decisão técnica interessante
- Resultado/métrica se tiver (ex: "handles X requests", "reduced query time by Y")

EDUCATION / SELF-STUDY
Self-taught developer — [período] — key areas: backend, full-stack, databases
```

**Nota:** como você não tem experiência formal ainda, a seção PROJECTS carrega o peso todo. Escreva ela com o mesmo cuidado que escreveria experiência de trabalho.

### Aula 2.3 — Erros comuns a evitar
- Não coloque foto (currículo americano/europeu não usa)
- Não coloque estado civil, idade, RG (irrelevante e estranho pra recrutador estrangeiro)
- Evite objetivo genérico tipo "seeking growth opportunities" — seja específico
- Não minta sobre nível de inglês — isso é testado na primeira call

## Módulo 3 — LinkedIn e GitHub

### Aula 3.1 — LinkedIn
- Foto profissional, mesmo que simples
- Headline: não deixe "Estudante" — use algo como "Backend Developer | Node.js, TypeScript, MySQL | Open to Remote Work"
- Ative "Open to Work" configurado especificamente pra "Remote" e países-alvo (EUA, Reino Unido, União Europeia)
- Seção "Featured": fixe seus 2-3 melhores projetos com link
- Publique 1x por semana sobre o que está aprendendo (aumenta muito o alcance orgânico com recrutador)

### Aula 3.2 — GitHub como vitrine
- Perfil com bio curta em inglês
- Pin nos 3 melhores repositórios
- Contribua com pelo menos 1 issue ou PR pequeno em projeto open source — isso soma muito, mesmo sendo simples (corrigir typo em doc já conta como primeiro passo)
- Mantenha um histórico de commits ativo — não precisa ser todo dia, mas evite hiato de meses

## Módulo 4 — Onde e como aplicar

### Aula 4.1 — Plataformas prioritárias
| Plataforma | Tipo | Observação |
|---|---|---|
| We Work Remotely | Vagas diretas | Grande volume, boa curadoria |
| RemoteOK | Vagas diretas | Filtro por "junior"/"entry level" |
| Wellfound (ex-AngelList) | Vagas em startups | Bom pra quem topa equity + salário menor no início |
| Toptal | Freelance/contrato | Processo seletivo rigoroso, mas paga bem |
| LinkedIn Jobs | Vagas diretas | Filtre por "Remote" + país |
| Comunidade #jobnagringa | Rede/indicação | Indicação vale muito mais que aplicação fria |

### Aula 4.2 — Estratégia de aplicação
- Não aplique só pra vaga "perfeita" — aplique também pra júnior/entry mesmo tendo mais skill, no início conta mais ter uma primeira experiência internacional no currículo
- Personalize a carta de apresentação (quando pedida) citando 1-2 coisas específicas da empresa, nunca genérico
- Aplique em lotes: reserve 2-3h por semana só pra aplicar, separado do tempo de estudo
- Peça indicação sempre que possível — comunidades como #jobnagringa existem exatamente pra isso

### Aula 4.3 — Processo seletivo típico (o que esperar)
1. **Triagem de currículo** (ATS + recrutador)
2. **Call inicial com recrutador** (fit cultural, inglês, expectativa salarial)
3. **Teste técnico ou live coding** — pratique em HackerRank, LeetCode (fácil/médio) e faça simulações no Pramp
4. **Entrevista técnica com o time** — geralmente revisam seu código de portfólio, então conheça cada linha do que você escreveu
5. **Entrevista final/fit** — geralmente com gestor
6. **Proposta** — aqui você negocia. Pesquise faixa salarial da vaga antes (Levels.fyi, Glassdoor)

### Aula 4.4 — Sobre pagamento internacional
Pra receber de empresa estrangeira morando no Brasil, as formas mais comuns são:
- **PJ direto com contrato internacional** + conta em plataforma como Wise, Payoneer ou Deel
- **Contratação via EOR** (Employer of Record — empresas como Deel, Remote.com, Rippling atuam como "empregador legal" no Brasil em nome da empresa estrangeira)
- Freelance/contrato via Toptal (eles cuidam do pagamento)

Evite combinar salário só em cripto como forma principal — é instável e a maioria das vagas estáveis paga em moeda fiduciária via essas plataformas.

Ao fim dessa fase, você deve ter:

4. Rotina semanal de aplicação (mínimo 10-15 aplicações qualificadas por semana)
